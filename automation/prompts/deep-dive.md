# 任务：深度文章写作

你会收到一个选定的深度选题（title / url / one_liner / why / angle），以及可能的补充材料。
先阅读 editorial-baseline.md 的编辑方针，然后写文章。

## 要求

- **只写中文版**。英文版在用户确认中文版之后另行生成
- 篇幅 1500–3000 字；宁可写透一个点，不要面面俱到
- 结构遵循编辑方针：叙事开场（具体事件/矛盾）→ 诊断（问题出在哪）→ 机制（为什么会这样，拆到原理层）→ 可操作判断（读者能带走什么）
- 标题即钩子：反直觉提问或尖锐命题；备选标题给 2 个
- 引用事实必须来自输入材料或广为人知的公开事实；拿不准的写「待核实」并列出自查清单
- **来源可追溯**：
  - 正文中每个关键事实/数字，首次出现处挂内联链接或标注（如 `（[论文](url)）`、`（arXiv:xxxx.xxxxx）`）
  - 文末（HTML 注释之前）加 `## 参考来源` 一节，列出写作时实际参考的每个来源：`- [标题](URL) — 用到了什么`
- 文末附「事实核查点」清单：列出文中每个需要人工核实的具体断言（供 PR 审核用）

## 执行约束

- 若可用 WebFetch/WebSearch 工具，先抓取选题 URL（及其引用的关键来源）再动笔，减少「待核实」项
- **最终回复只包含文章文件内容本身**：不要解说、不要提问、不要描述你做了什么、不要尝试自己写文件

## 输出格式

一个完整的 Markdown 文件内容：

```
---
title: <主标题>
description: <一句话>
pubDate: <YYYY-MM-DD>
tags: [<1-3 个标签>]
lang: zh
slug: <english-slug>
translationOf: <同 slug，英文版未来使用>
---

<正文>

<!--
备选标题：
1. ...
2. ...

事实核查点：
- [ ] ...
-->
```
