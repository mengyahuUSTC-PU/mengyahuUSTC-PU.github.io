# 任务：每周运营周报

你会收到：①本周 GA4 + Search Console 数据 JSON；②上一期周报全文（若存在）；③本周发布的文章列表。
先阅读 editorial-baseline.md，然后写周报（中文，收件人是作者本人）。

## 结构（依次）

1. **上期建议复盘**（有上期周报时必须放在最前）：逐条核对上期「下一步建议」——做了没有？有效果吗（用本周数据说话）？没做的说明是否还值得做。没有上期周报时写「首期，无复盘项」
2. **总体判断**：一句话概括本周（增长/平稳/异常）。主指标是 `headline` 里的**有效访问（engagedSessions）和回访用户（returning_users）**，与 `headline_previous_week` 对比；sessions 只作参考。`suspected_bot_sessions` 非空时，用一句话说明哪些国家的多少次访问像机器人（几乎零停留、只看一页），不计入判断
3. **渠道趋势**：各来源带来多少有效访问（engagedSessions），谁在涨谁在跌，值不值得调整分发策略
4. **内容表现**：Top/Bottom 文章（浏览、停留），并推断原因（题材？分发时机？标题？）
5. **搜索表现**：GSC 的展示/点击/热门 query，收录情况
6. **分发复盘**：本周发出的社交帖效果与文章点击的对应关系。分发记录里 status=expired 表示作者选择不发社交（提醒一次后 7 天自动作废），不是积压，不要建议补发；只有 status=pending 才是待决定；**发布模式对比**：按「晚间即时发」vs「高峰时段定时发」分组（依据分发发布记录的时间戳），对比两组带来的 UTM sessions 与互动，给出目前更优的一方；每组样本 <3 篇时必须明说「样本不足，仅记录不下结论」，并持续逐周累积这项对比
7. **订阅与转化**：本周新增/流失订阅者；转化率=新增订阅者÷本周有效访问，横向跟踪这个数字的周变化；newsletter 每周日发一封合集，效果看 newsletter UTM 带来的有效访问；判断瓶颈在「流量太小」还是「转化太差」，二者的对策完全不同，必须点名当前瓶颈
8. **下一步建议**：≤3 条，每条要具体可执行、下期可核对（避免"继续保持"这类空话）。**其中需要作者本人动手的最多 1 条**；其余写成管线可以做的改进，开头标「给管线：」，由 Claude Code 在月度优化日统一实施。上期建议连续两期没执行的，在复盘里写一句「撤下」，不再滚动

## 风格

- 数字说话，判断给机制；不堆表格，重点数字写进句子里
- 站点刚起步时数据小是常态——小基数下不要过度解读日间波动，明确说「样本太小不构成结论」
- 全文 ≤600 字；每个数字只出现一次，不在结尾复述

**最终回复只包含周报 Markdown 全文**（以 `# 周报 YYYY-MM-DD` 开头），不要解说。
