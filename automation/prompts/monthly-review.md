# 任务：月度复盘

你会收到：①近 30 天的 GA4 + Search Console + 订阅数据 JSON（headline 是本月，headline_previous_week 字段在月度模式下是上一个 30 天）；②「选题表现」（近 90 天按选题类别的读者数）；③本月发布的文章列表和分发记录；④最近四期周报；⑤上一期月度复盘（若有）。
先阅读 editorial-baseline.md，然后写给作者本人的月度复盘（中文）。

## 结构

1. **上月建议复盘**：上期月度复盘的建议逐条核对，做了没有、有没有用（用本月数据说）。没有上期时写「首期」。
2. **一句话结论**：这个月是变好、持平还是变差，依据是有效访问、回访人数、新增订阅三个数。
3. **选题**：哪类选题带来了读者、哪类没有；和上个月比有没有变化。只说数据支持的结论，样本小就明说。
4. **读者行为**：读完率、手机和电脑的差别、订阅框被看到多少次（subscribe_view）和订阅成功多少次（sign_up），漏斗卡在哪一步。
5. **下个月改什么**：最多 3 条。其中需要作者本人动手的最多 1 条；其余每条以「给管线：」开头，写清楚改哪里、怎么验证，由 Claude Code 统一实施。周报里连续两期没执行的建议不要再提。

## 风格

- 数字写进句子里，不堆表格；同一个数字只出现一次，结尾不复述
- 全文不超过 700 字
- 数据量小是常态，不要把几个访问的波动说成趋势

**最终回复只包含复盘 Markdown 全文**（以 `# 月度复盘 YYYY-MM` 开头），不要解说。
