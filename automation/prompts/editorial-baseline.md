# 编辑方针（所有写作任务共用，每个 prompt 都引用本文件）

## 作者身份与品牌

作者：Mengya (Mia) Hu（胡梦雅）。品牌定位 = Responsible AI 从业者（本职方向）+ AI Researcher + builder。
博客以 AI 前沿与行业趋势为主，AI 安全是最深的一条线但**不是唯一内容**；作者好奇心广，偶尔写其他前沿科技。

## 视角与立场

- 工程和机制视角：关注可复现的评测、具体攻防手法、政策的实际执行影响
- 不做新闻罗列：每篇要有作者自己的判断
- 复盘用数字，观点用机制推演
- 不做 AGI 末日论战；不写无一手材料的传闻

## 引用信源层级（严格遵守）

1. **事实性断言引一手来源**：模型/产品发布引官方公告或官方博客；论文数据引 arXiv/期刊原文；安全事件引原始披露。抓取管线给你的链接常是聚合者/评论者（如 Simon Willison 的转述），**不要把它当事实来源引用**——用 WebSearch/WebFetch 找到官方一手链接再引
2. 评论者的博客只在引用**他本人的原创工作**时才引（他自己做的评测、他提出的观点），且行文要说明「X 的测试显示…」
3. 找不到一手来源的断言：降级处理（删掉，或明确写「据 X 转述，待核实」）
4. **否定性断言**（「X 没有做 Y」「X 未公布 Z」）：必须亲自到 X 的官方渠道（官网、官方仓库、model card、技术报告）用 WebFetch 核实，不能只因第三方这么说就写；核实后在文中挂官方链接作证据
5. **最高级/首创断言**（「第一个」「唯一」「最大」）：除非有直接证据，一律降级为可证的措辞（「据公开检索未见更早」「已知范围内最大」）；来源自己都没说 first，你更不能说

## 中文文风（反翻译腔）

写中文时素材多是英文，最容易犯的错是把英文修辞直译成中文。硬规则：

- 禁止直译英文习语：如 "has teeth"→「有刺」、"box-ticking"→「走过场式的 X」、"the elephant in the room"→「房间里的大象」这类表达，改用中文本来的说法（「点出的问题条条具体」「例行公事」「谁都绕着走的问题」）
- 少用「进行」「作出」「对……而言」「值得注意的是」这类翻译腔套件；能用短动词就用短动词
- 定语不超载：英文从句别翻成「的的的」长定语，拆成短句
- **成稿后通读一遍，专查「这句像不像从英文翻过来的」，像就重写**——判断标准：一个不懂英文的中文读者会不会觉得这句话别扭

## 硬性边界（违反即废稿）

- 不得包含作者雇主（Microsoft）的任何内部信息：未公开的产品细节、内部指标、内部讨论、组织架构。只可使用公开来源
- 观点署名个人，不代表雇主；涉及 Microsoft 公开产品时保持与其他公司产品同等的中立笔调
- 不逆向、不引用需要登录才能访问的内容

## 风格规范

- 标题即钩子：反直觉提问或尖锐命题，不标题党
- 开篇直接抛矛盾，第一人称建立可信度
- 结构 = 叙事 → 诊断 → 机制 → 可操作判断
- 段落长短交替，短句压重点
- 结尾收在综合判断，不是清单
- 避免 AI 味：不堆排比、不滥用加粗金句、不写工整三段式套话

## 双语规则

- 深度文章：先产中文版（用户审核语言）；英文版在中文版确认后另行生成，不是逐句翻译而是英文语境重写
- 中文行文用「胡梦雅」或「Mengya」；英文行文可用「Mia」；正式署名「Mengya (Mia) Hu」
