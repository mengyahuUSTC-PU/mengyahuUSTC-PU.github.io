8 月 5 日，Neon 发了一篇和 RL 训练平台 Castform 合写的[博客](https://neon.com/blog/how-castform-neon-beats-frontier-models-on-price-and-efficiency)，核心宣称一句话：一个 40 亿参数（4B）的开源模型，经过任务定向的强化学习后训练，在检索任务上做到与 GPT-5.6 Sol 相当的准确度，推理成本低 100 倍。

参照物不弱。GPT-5.6 Sol 是 OpenAI 当前的旗舰，官方定价每百万输入 token 5 美元、输出 30 美元（[OpenAI 文档](https://developers.openai.com/api/docs/models/gpt-5.6-sol)）。博客给的现状数字：用它跑一次多轮搜索请求，10 秒以上，约 0.03 美元。

先交代利益相关。这是两个卖铲子的人合写的文章：Castform 卖 RL 后训练平台（[今年 6 月 11 日开放预览](https://castform.com/blog/beta-launch/)），Neon 是 Databricks 在 2025 年 5 月[花 10 亿美元收购](https://techcrunch.com/2025/05/14/databricks-to-buy-open-source-database-startup-neon-for-1b/)的 Postgres 云数据库公司，在这套方案里卖存语料和检索的数据库。评测用的是他们自定义的「平均评估奖励」，没公布基座模型是哪个、没用公开 benchmark、没给具体准确率数字。所以「追平」两个字，我建议先打个问号。

但这篇仍然值得拆。因为它描述的机制成立与否，并不取决于这一篇博客的数字可信与否。

## 检索为什么贵到值得单独养一个模型

先把任务本身讲清楚。传统 RAG（检索增强生成）是一问一搜一答：把用户问题变成一次查询，从文档库里取回相关段落，让模型据此作答。现在主流做法变成了所谓 agentic 检索：模型在一个循环里自己规划，搜一次、看结果、发现不够、改写查询、再搜，直到凑齐证据才作答。

贵就贵在这个循环上。每多搜一轮，之前所有轮次的搜索结果都要重新塞回上下文里再算一遍，token 消耗随轮数叠加，而不是线性增加。单次 0.03 美元看着无所谓；但如果这是一个面向用户的搜索功能，每天一百万次请求就是 3 万美元，一年上千万。检索恰好是「高频、窄、重复」的典型：它是很多产品的每一次交互都要过的路，不是偶尔跑一次的高难推理。

顺带说一句，这套方案里的检索工具本身毫无秘密：语料存在 Postgres 里，用关键词匹配加语义相似度的混合搜索。基础设施是大路货，所有宣称的差距都来自模型侧的训练。

## 小模型凭什么追平：溢价买的是通用性，而窄任务用不到

GPT-5.6 Sol 这个档位的模型，贵在什么都会。但「把用户问题改写成更好的搜索查询、判断取回的段落够不够」这个任务，用不到什么都会。窄任务上决定表现的，是模型对这个特定工具、特定语料、特定评分标准的适配程度，知识广度帮不上太多忙。

微调小模型在窄任务上追平大模型，不是新现象。用 SFT（监督微调：拿标注好的输入输出对，让模型模仿）做这件事，从 GPT-4 时代就是成熟操作。Castform 的差异在于用强化学习：不给标准答案，只给一个打分器（奖励函数），让模型在环境里自己试错，按得分调整。

为什么检索任务适合这条路？因为多轮搜索的「标准答案」很难人工标注：第三轮该把查询改写成什么样，没人能写出黄金示范。但结果好不好，机器很容易打分：取回的文档对不对、引用是否指向真实存在的段落、最终答案是否正确，都能自动核对。**难示范、易打分，正是 RL 相对 SFT 的适用区。**博客里的奖励函数就是按这三项（检索、引用、答案正确性）计分的。

还有一个位置问题值得交代：后训练（post-training）本来是模型厂出厂前的最后一道工序，预训练之后、发布之前，由 OpenAI、Anthropic 这类厂商自己做。Castform 这类平台做的事，是把这道工序拆出来，做成应用团队的自助服务。这个产品形态是不是它首创，博客没说，我也不替它说；但「把 RL 后训练平台化」确实是把过去只有模型厂能做的事往下游推了一层。

## 100 倍的账，哪几处要打折

第一处：对比的是 API 牌价和自托管小模型的推理成本。API 按 token 付费，用多少付多少；自托管的 GPU 按小时烧钱，流量低谷照付。高频任务能把利用率打满，这笔账算得平；低频任务摊不平，百倍差距会大幅缩水。有意思的是，Castform 自己 6 月的发布博客里说的是开源模型比 API「便宜 10 到 20 倍」，到了这篇联合营销文里变成了 100 倍。两个数字都出自同一家之口，口径差了近一个量级，这本身就说明这类倍数取决于怎么算。

第二处：训练成本没进账。GPU 时钱是小头，大头是数据工程。博客自己承认：大多数公司并没有现成的干净任务和奖励数据集，把私有数据变成能训练的任务集，需要「大量数据工程和人工标注」。奖励函数的设计更是隐性成本：打分器写歪了，模型会学会钻打分器的空子而不是把任务做好，这在 RL 里是常见故障，行话叫 reward hacking。

第三处：任务会漂移。语料换了、工具改了、产品需求变了，用前沿 API 的团队改一段 prompt 就能跟上；自训模型的团队要重新走一遍训练。这是一台跑步机，上去之前要想清楚下不下得来。

## 什么任务值得复制这条路

把上面的机制归拢，这条路划算需要三个条件同时成立：任务窄、流量高、结果能被机器验证。检索三条全占，所以它是最好的示范案例。SQL 生成、结构化信息抽取、分类打标，也基本满足。

反过来看不满足的情形。开放式写作难验证，打分器给不出可靠奖励。写操作类的 agent 任务（改数据库、发邮件、下单）能验证结果，但试错代价高：训练时必须给模型隔离环境，不能让一个还在犯错的模型碰生产数据。Neon 博客把「有状态 agent 需要隔离环境」列为下一步方向，说明这一块现在还没做好。低频任务和快速变化的任务，继续用前沿 API 更省。

这类厂商评测的正确读法，不是相信具体数字，而是注意卖铲子的人在往哪个方向修路。Databricks 花 10 亿美元买下 Neon，再和 RL 训练平台联合发这种文章，押的是同一个判断：企业 AI 的推理开支会大到值得为单个高频任务养专用模型。我倾向于认为高频窄任务的推理会持续从前沿 API 向专用小模型迁移，但门槛不在训练算法，在于谁替你把数据工程和奖励设计做掉。这恰好是这两家想卖的东西，也是整篇博客里最值得当真的一句承认：最难的一步，被他们写在了自家的限制说明里。
