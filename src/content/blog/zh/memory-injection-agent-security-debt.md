8 月 25 日这天,Anthropic 把 Claude 的记忆统一成一套:chat 里记住的东西,Claude Cowork 在云端跑任务时也能用,反过来也一样。这项能力在 Free、Pro、Max 三档默认开启,记忆不再是对话结束后回顾生成,而是你聊着聊着就即时写进去([Anthropic 公告](https://claude.com/blog/claudes-memory-works-everywhere-and-you-decide-whats-in-it))。对用户是省事:不用反复交代自己是谁、项目进展到哪。

同一天,arXiv 上挂出一篇叫 InjecMEM 的论文([arXiv:2608.23471](https://arxiv.org/abs/2608.23471v1),已被 COLM 2026 接收),结论正好戳在这项能力的软肋上:一个只能像普通用户那样跟 agent 对话、拿不到记忆库读写权限的人,可以只用一次交互,就把一条恶意记录塞进 agent 的持久记忆,让它在之后相关的查询里反复生效。

时间点是巧合,但这两件事放在一起说明一个事:记忆一旦从"单次对话的临时上下文"变成"跨会话、默认开启的持久存储",它就同时变成了一个新的攻击面。而且这个攻击面,是功能上线那一刻就存在的,不是以后才冒出来的。

先说清楚一件事,免得误会。InjecMEM 的实验对象是两个开源记忆框架——MemoryOS 和 MemGPT,不是 Claude 的记忆系统;论文没有、也没法测 Anthropic 的闭源实现。这是一篇学术评测,不是一起已经发生的生产事故。我拿 Cowork 当引子,是因为它代表了"持久记忆正在成为主流 agent 产品的默认配置"这个趋势,而 InjecMEM 揭示的是这类系统共有的结构性风险——不是说 Cowork 已经被这么攻破了。

## 攻击到底怎么进去的

要理解这个攻击,先得知道 agent 的记忆通常怎么运作。它不是把你说过的每句话都原样存下来再全部塞回模型——那样上下文窗口早就爆了。主流做法是 RAG:把对话内容拆成一条条记录、算成向量存进记忆库;等你下次提问时,系统按语义相似度从库里检索出最相关的几条,拼进 prompt 再交给模型。也就是说,能不能被"想起来",取决于你的新问题和某条旧记录在向量空间里够不够近。

InjecMEM 的攻击就是冲着这套检索机制设计的,分两部分。

第一部分论文叫"锚点"(anchor),作用是保证被污染的记录能被检索到。攻击者不知道目标系统具体用哪个检索器、怎么算相似度,所以锚点被做成"检索器无关"的:它塞进一堆围绕目标话题的高召回线索,既在语义向量上贴近该话题,也在关键词上重叠。这样不管底层用什么嵌入模型,只要受害者以后问起这个话题,这条毒记录就大概率被捞出来。

第二部分是"对抗命令"(adversarial command)——真正干坏事的那句短指令。它是被梯度优化出来的,目标是在各种不确定的环境里都还能生效:记忆被检索出来后会和别的内容拼在一起,位置不固定、周围噪声多、整个 prompt 可能很长,这条命令要在这些条件下都不失效。

至于这条毒记录怎么进库的,有两条路。直接的一条是攻击者自己作为用户跟 agent 聊一次,内容被记进去;间接的一条更值得担心——如果 agent 会把工具返回的内容(比如它抓取的一个网页、读到的一封邮件)也写进记忆,那么攻击者只要控制了 agent 会去读的某个外部内容,就能隔空投毒,连和 agent 直接对话都不需要。

## 这不是第一次,但门槛又降了一截

"只用查询、拿不到记忆库权限就能投毒"这个威胁模型,不是 InjecMEM 首创。2025 年 3 月的 MINJA([arXiv:2503.03704](https://arxiv.org/abs/2503.03704),USENIX Security 2025)已经证明过:任何普通用户都能通过 query-only 的交互影响 agent 记忆,它报告的注入成功率高达 98.2%。所以这条路早就通了,InjecMEM 不是发现了一个全新的洞。

两者的机制不一样,这也是 InjecMEM 的新意所在。MINJA 靠的是"桥接步骤"——诱导 agent 在处理受害者问题时,一步步走进攻击者预设的恶意推理链。InjecMEM 换了个角度,把重心放在检索这一层的鲁棒性上:用检索器无关的锚点保证"被想起来",用梯度优化的命令保证"想起来之后还管用"。它更像是在系统性地拷问"一条毒记录要在真实的 RAG 检索、拼接、长上下文里活下来并生效,需要满足什么条件"。

## 数字说明了什么

InjecMEM 用了三个指标,分开看才有意义:

- **RSR(检索成功率)**:受害者提问时,毒记录被检索命中的比例;
- **ASR-c(条件攻击成功率)**:在毒记录已经被检索出来的前提下,那条对抗命令真正生效的比例;
- **ASR-j(端到端攻击成功率)**:一次查询里既被检索命中、命令又生效的整体比例。

在分层记忆系统 MemoryOS 上,首次查询的 RSR 是 61.2%,ASR-c 是 76.6%,乘下来端到端的 ASR-j 是 35.6%。翻译成人话:攻击者投一次毒,受害者之后每问三次相关问题,大约就有一次会踩中被污染的输出。在结构更简单的 MemGPT 上这组数字低一些(RSR 37.2%、ASR-c 48.6%、ASR-j 18.1%),但也远不是可以忽略的水平。

比单次成功率更值得注意的是持久性。记忆库不是静态的——你正常用 agent,新记录会不断写进去,理论上会把旧的毒记录慢慢"冲淡"。论文追踪了这个衰减:毒记录被检索命中的概率,从第 1 次查询的 61.2%,到 10 次查询后仍有 48.8%,到 50 次查询后还有 35.4%。也就是说,一次注入的影响不是打一枪就没,它能在几十轮正常使用里持续潜伏。对一个你天天用、记忆越攒越多的 agent 来说,这意味着投毒的"半衰期"相当长。

## 为什么不好防

直觉上,防御应该不难:在记忆被检索出来、送进模型之前,加一道过滤器把可疑记录拦掉不就行了?论文测了四种这样的"检索时过滤",结果不太乐观。

三种基于语义判断的过滤器——用 LLM 当裁判、用 ProtectAI、用 PromptGuard——几乎不误伤正常记忆(良性拦截率都低于 1%),但对攻击的削减也很有限:端到端成功率只从三成多压到两成七上下,毒记录照样有相当概率漏过去。原因不难理解:InjecMEM 的锚点本来就是伪装成正常话题内容的,对抗命令也是优化来躲过这类判断的,语义过滤器很难把它和真实记忆干净地分开。

唯一真正有效的是基于困惑度(perplexity)的过滤——它靠"这段文字读起来是否别扭、不像自然语言"来判断,能把被梯度优化过、往往显得生硬的对抗命令识别出来,把检索命中率压到接近零。但代价是它同时误杀了 71.8% 的正常记忆。这是个没法回避的安全-可用性取舍:把过滤器调到能挡住攻击,记忆功能本身也基本废了。

这就是记忆系统作为攻击面的麻烦之处。它把 prompt injection 的老问题(模型分不清"数据"和"指令")和 RAG 检索、持久化存储叠在了一起:注入不再是一次性的,而是被存下来、反复检索、长期生效;而检测又卡在"毒内容长得像正常内容"这个根本困难上。

## 能带走的判断

对做 agent 产品的人,我的看法是几条具体的:

**别让不可信来源的内容默默进记忆。** 最危险的是间接注入——工具抓来的网页、读到的邮件、别人共享的文档,如果这些内容会自动写进持久记忆,攻击面就从"愿意跟你对话的人"扩大到"能往你 agent 视野里放内容的任何人"。至少要区分记忆的来源可信度,来自外部工具的内容进记忆前应当有独立的审查环节,而不是和用户亲口说的话一视同仁。

**把记忆的读取和写入当成有权限边界的操作,而不是透明缓存。** 检索时的语义过滤靠不住,但不代表什么都做不了:记录来源标注、写入速率限制、跨用户的记忆隔离、敏感操作前对记忆内容的二次确认,这些工程手段单独都不够强,叠起来能抬高攻击成本。

**给用户看得见、删得掉的控制权。** 这一点 Anthropic 的做法值得参考:记忆按主题逐条可见、可编辑、可删除,敏感话题默认不存。当自动检测靠不住时,让用户能审查和清理自己的记忆,是最后一道也是很实在的一道防线。

对普通用户,一句话:记忆功能好用,但它记住的不只是你告诉它的东西。如果你的 agent 会自动读取外部内容并存进记忆,偶尔翻一翻它到底记住了些什么、把不认识或不对劲的条目删掉,是值得养成的习惯——尤其是在你打算让它跨会话、跨任务持续替你做事的时候。

记忆让 agent 更像一个能长期共事的助手,这是真实的进步。但持久记忆不是白拿的能力,它同时是一笔安全债——你在功能上线那天就欠下了,只是账单会晚一点到。
