### [Bun 的 Rust 重写版已随 Claude Code 上线](https://bun.com/blog/bun-in-rust)

Bun 创始人 Jarred Sumner 本月宣布，他用并行运行的 Claude agent 集群，在 11 天里把 Bun 约百万行 Zig 代码重写成了 Rust。当时不少人把它当成一场演示，但 [Simon Willison 的实测](https://simonwillison.net/2026/Jul/19/claude-code-in-bun-in-rust/)显示这版已经进了生产：他翻检自己机器上的 Claude Code 二进制，发现内嵌的是尚未公开发布的 Bun v1.4.0，里面带着 563 个 Rust 源文件路径——官方称 Linux 上启动快约 10%，而几乎没有用户察觉到切换。这件事的意义不在快那 10%，而在于一个由 AI 大规模重写的运行时，已经悄悄承载起 Claude Code 全部用户的日常使用。「AI 写的代码能不能进关键路径」不再是假设题；接下来更值得追问的是它的审查流程和回滚机制长什么样。

### [纽约市拟要求房源图片披露 AI 生成与修饰](https://www.nyc.gov/mayors-office/news/2026/07/mayor-mamdani-releases--rental-ripoff-report---outlining-new-act)

纽约市长 Mamdani 发布「Rental Ripoff Report」，在 23 项租房改革建议中专门写了一条针对 AI：房东、中介和挂牌平台使用 AI 生成或数字修饰的图片视频时，必须做「清晰醒目」的披露，由市消费者与劳工保护局会同 StreetEasy、Zillow 等平台执行。生成式工具已经把虚拟布置的成本压到接近零——空房秒变精装、裂缝一抹就平，租客往往到看房那一刻才发现落差。AI 内容披露义务此前主要落在选举广告和新闻上,这次进入了普通人金额最大的日常交易之一；而把执行抓手放在平台侧、不去逐个追房东，是少数在执行层面说得通的设计。注意这目前是建议而非已生效法规，预计分阶段落地。

### [LoopGain：用控制论替代 max_iterations 给 agent 循环装刹车](https://github.com/loopgain-ai/loopgain)

一个 Apache-2.0 的纯 Python 库把 1921 年的 Barkhausen 稳定性判据搬进了 agent 循环：逐轮测量误差比值 E(n)/E(n-1)，将轨迹分为收敛、停滞、震荡、发散四种状态，据此决定继续、停止，还是回滚到目前最优的输出，并提供 LangGraph、CrewAI、Claude Agent SDK 等适配器。作者对边界也说得直白：它检测的是「收敛」而非「正确」，基准测试里有 4.5% 的收敛结果通过了环内检查、却在保留测试集上失败。agent 可靠性工程正在从拍脑袋设上限，走向有信号、可度量的运行时控制——但验证器的质量仍是整套方案的天花板。

### [Codex 一次 PR 把两个模型的上下文窗口从 372k 下调到 272k](https://github.com/openai/codex/pull/33972)

OpenAI 在 Codex 仓库一个名为「刷新捆绑模型元数据」的 PR 里，把 gpt-5.6-sol 和 gpt-5.6-terra 两个模型的 context_window 从 372k 降到 272k，缩水约 27%，已于 7 月 18 日合并，没有任何公告或说明。能力上限的变更靠 JSON diff 而不是变更日志对外沟通，对工程用户是个提醒：你依赖的上下文预算，可能在某次客户端更新里就变了，围绕上限设计的长文档流程最好留出余量。

**今日一句话**：今天几条新闻共享同一个母题——AI 产出进入现实的速度，已经快过我们核实它的手段。于是有人去翻二进制求证，有人立规矩要求披露，有人给循环装上刹车；「核实」正在从美德变成基础设施。
